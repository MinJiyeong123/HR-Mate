# 데모 가이드 (8단계)

포트폴리오 시연용 가상 사원 데이터를 개발 DB(`hr_mate`)에 넣고, 화면에서 주요 기능을 보여 주는 방법입니다.

> - 모든 데이터는 가상입니다. 실존 인물과 무관하며 민감정보(주민등록번호, 주소, 계좌번호 등)는 없습니다.
> - 이메일은 예시용 예약 도메인(`example.com`)만 사용하고, 전화번호는 비워 둡니다.
> - 테스트 DB(`hr_mate_test`)와 자동 테스트 설정에는 영향이 없습니다.

## 2. 데이터 넣기 전에 알아 둘 점

- **초기화는 필요 없고 하지 않습니다.** 파일은 새 행을 추가(INSERT)만 하고 기존 행은 수정·삭제하지 않습니다.
- **백업은 필수가 아닙니다.** 파일이 기존 데이터를 바꾸지 않기 때문입니다. 원하면 HeidiSQL의 내보내기 기능으로 백업할 수 있으며, 백업 파일은 Git에 넣지 않습니다.
- **여러 번 실행해도 안전합니다.** 같은 사번이 이미 있으면 그 행은 건너뛰고, 값을 바꾸지 않습니다.
- **한 번 넣은 데이터는 되돌리기 어렵습니다.** 이 프로젝트는 행을 물리적으로 삭제하지 않으며, 화면의 삭제는 논리 삭제라 사번이 계속 사용 중으로 남습니다.
- 12명이 한 문장으로 들어가므로, 오류가 나면 12명 모두 들어가지 않습니다.
- 파일 끝의 `COMMIT;`이 입력을 확정합니다. 자동 커밋이 켜져 있으면 아무 영향이 없습니다.
- 파일 내용은 자동 테스트(`SampleDataScriptTest`)가 테스트 DB에서 미리 실행해 보고 롤백하는 방식으로 검증합니다. (테스트는 `COMMIT`을 실행하지 않습니다.)

> ⚠️ **확정(커밋)되지 않은 입력은 그 세션에서만 보입니다.**
> 자동 커밋이 꺼진 세션에서 INSERT만 실행하면, 같은 HeidiSQL 세션에서는 12명이 보여도 백엔드·브라우저에서는 보이지 않고,
> 세션을 닫으면 입력이 취소됩니다(팝업 없이). 이때 AUTO_INCREMENT 값만 올라가고 행은 남지 않습니다.
> 그래서 결과는 반드시 **새 세션이나 브라우저**에서 확인합니다. (2026-09-28 첫 적용 때 실제로 이 문제로 데이터가 남지 않았습니다.)

## 3. HeidiSQL에서 데이터 넣기

1. **실행 전 기준값 확인** (`HR Mate - app` 세션, 조회만)

   ```sql
   SELECT @@autocommit;
   SELECT COUNT(*) FROM hr_mate.employee;
   ```

   - `@@autocommit`이 `1`인지 확인합니다. `0`이어도 파일 끝의 `COMMIT;`이 확정하지만, 값은 기록해 둡니다.
   - 사원 수를 기록합니다.

2. **파일 불러오기**: 메뉴 **파일 → SQL 파일 불러오기** → `docs/sample-data/sample-employees.sql`
   - 반드시 `HR Mate - app` 세션(hrmate_app 계정)에서 엽니다. root나 test 세션이 아닙니다.
   - 파일 윗부분에 `USE hr_mate;`, 맨 끝에 `COMMIT;`이 있는지 확인합니다.

3. **실행**: **F9** → 아래 메시지 영역에서 오류가 없는지 확인합니다. (INSERT와 COMMIT이 모두 실행되어야 합니다.)

4. **결과 확인 — 반드시 새 세션에서** (조회만)
   - 실행한 세션을 닫고 `HR Mate - app` 세션을 **새로 연 뒤** 조회합니다. 같은 세션의 조회만으로는 확정 여부를 알 수 없습니다.

   ```sql
   SELECT COUNT(*) FROM hr_mate.employee;
   SELECT employment_status, COUNT(*) FROM hr_mate.employee GROUP BY employment_status;
   ```

   - 처음 넣는 경우: 1번 값 + 12 (0에서 시작했다면 12), `ACTIVE` 10 / `RESIGNED` 2
   - 이미 넣은 적이 있다면 건수가 늘지 않아야 합니다.

5. **브라우저 확인**: 백엔드와 프론트엔드를 실행하고 사원 목록에 12명, 요약 카드 12 / 10 / 2가 나오는지 확인합니다.
   - HeidiSQL에서는 보이는데 브라우저에서 보이지 않으면 입력이 확정되지 않은 것입니다. 실행한 세션을 닫기 전에 알려 주세요.

6. **(선택) 중복 방지 확인**: 3번을 한 번 더 실행하고 4번 결과가 그대로인지 확인합니다.

## 4. 화면 시연 순서

백엔드(`.\gradlew.bat bootRun`)와 프론트엔드(`npm run dev`)를 실행하고 http://localhost:5173 을 엽니다.

1. **목록**: 12명, 요약 카드 전체 12 / 재직 10 / 퇴사 2, 재직·퇴사 배지, 퇴사일 표시, 비어 있는 항목 "-"
2. **상세**: 이름을 눌러 프로필·소속·연락처·재직 정보 확인
3. **사번 중복 확인**: 등록 화면에서 `e2019001` 입력 → 대문자 변환 후 "이미 사용된 사번입니다." / `E2026001` → "사용 가능한 사번입니다."
4. **입력 검증**: 하이픈 없는 전화번호, 잘못된 이메일 → 항목별 오류 문구
5. **등록**: `E2026001`로 가상 사원 등록 → 목록에 추가, 새로고침해도 유지
6. **퇴사 처리와 정정**: 수정 화면에서 퇴사 선택 → 퇴사일 필수, 입사일보다 이른 날짜 거부 → 저장 / 다시 재직으로 정정하면 퇴사일이 비워짐
7. **논리 삭제**: 5번에서 등록한 사원 삭제 → 목록에서 제외 → 같은 사번으로 중복 확인하면 "이미 사용된 사번입니다."
8. **장애 안내**: 백엔드를 끄고 목록을 새로고침 → "서버에 연결할 수 없습니다" 안내와 다시 시도 버튼

> 5~7번에서 등록·삭제한 사원은 개발 DB에 남습니다. 시연을 반복할 때는 `E2026002`, `E2026003`처럼 매번 다른 사번을 사용하세요.
