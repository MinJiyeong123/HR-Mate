# 데모 가이드

포트폴리오 시연용 가상 사원 데이터를 개발 DB(`hr_mate`)에 넣고, 화면에서 사원 관리와 급여 관리·연간 급여 집계(시뮬레이션), 연말정산(모의 계산) 기능을 보여 주는 방법입니다.

> - 모든 데이터는 가상입니다. 실존 인물과 무관하며 민감정보(주민등록번호, 주소, 계좌번호 등)는 없습니다.
> - 이메일은 예시용 예약 도메인(`example.com`)만 사용하고, 전화번호는 비워 둡니다.
> - 테스트 DB(`hr_mate_test`)와 자동 테스트 설정에는 영향이 없습니다.

## 2. 데이터 넣기 전에 알아 둘 점

- **초기화는 필요 없고 하지 않습니다.** 파일은 새 행을 추가(INSERT)만 하고 기존 행은 수정·삭제하지 않습니다.
- **백업은 필수가 아닙니다.** 파일이 기존 데이터를 바꾸지 않기 때문입니다. 원하면 HeidiSQL의 내보내기 기능으로 백업할 수 있으며, 백업 파일은 Git에 넣지 않습니다.
- **여러 번 실행해도 안전합니다.** 같은 사번이 이미 있으면 그 행은 건너뛰고, 값을 바꾸지 않습니다.
- **한 번 넣은 데이터는 되돌리기 어렵습니다.** 이 프로젝트는 행을 물리적으로 삭제하지 않으며, 화면의 삭제는 논리 삭제라 사번이 계속 사용 중으로 남습니다.
- 12명이 한 문장으로 들어가므로, 오류가 나면 12명 모두 들어가지 않습니다.
- 파일 끝의 `COMMIT;`이 입력을 확정합니다. 자동 커밋이 켜져 있으면 아무 영향이 없습니다.
- 파일 내용은 자동 테스트(`SampleDataScriptTest`)가 테스트 DB에서 미리 실행해 보고 롤백하는 방식으로 검증합니다. (테스트는 `COMMIT`을 실행하지 않습니다.)

> ⚠️ **확정(커밋)되지 않은 입력은 그 세션에서만 보입니다.**
> 자동 커밋이 꺼진 세션에서 INSERT만 실행하면, 같은 HeidiSQL 세션에서는 12명이 보여도 백엔드·브라우저에서는 보이지 않고,
> 세션을 닫으면 입력이 취소됩니다(팝업 없이). 이때 AUTO_INCREMENT 값만 올라가고 행은 남지 않습니다.
> 그래서 결과는 반드시 **새 세션이나 브라우저**에서 확인합니다. (2026-09-28 첫 적용 때 실제로 이 문제로 데이터가 남지 않았습니다.)

## 3. HeidiSQL에서 데이터 넣기

1. **실행 전 기준값 확인** (`HR Mate - app` 세션, 조회만)

   ```sql
   SELECT @@autocommit;
   SELECT COUNT(*) FROM hr_mate.employee;
   ```

   - `@@autocommit`이 `1`인지 확인합니다. `0`이어도 파일 끝의 `COMMIT;`이 확정하지만, 값은 기록해 둡니다.
   - 사원 수를 기록합니다.

2. **파일 불러오기**: 메뉴 **파일 → SQL 파일 불러오기** → `docs/sample-data/sample-employees.sql`
   - 반드시 `HR Mate - app` 세션(hrmate_app 계정)에서 엽니다. root나 test 세션이 아닙니다.
   - 파일 윗부분에 `USE hr_mate;`, 맨 끝에 `COMMIT;`이 있는지 확인합니다.

3. **실행**: **F9** → 아래 메시지 영역에서 오류가 없는지 확인합니다. (INSERT와 COMMIT이 모두 실행되어야 합니다.)

4. **결과 확인 — 반드시 새 세션에서** (조회만)
   - 실행한 세션을 닫고 `HR Mate - app` 세션을 **새로 연 뒤** 조회합니다. 같은 세션의 조회만으로는 확정 여부를 알 수 없습니다.

   ```sql
   SELECT COUNT(*) FROM hr_mate.employee;
   SELECT employment_status, COUNT(*) FROM hr_mate.employee GROUP BY employment_status;
   ```

   - 처음 넣는 경우: 1번 값 + 12 (0에서 시작했다면 12), `ACTIVE` 10 / `RESIGNED` 2
   - 이미 넣은 적이 있다면 건수가 늘지 않아야 합니다.

5. **브라우저 확인**: 백엔드와 프론트엔드를 실행하고 사원 목록에 12명, 요약 카드 12 / 10 / 2가 나오는지 확인합니다.
   - HeidiSQL에서는 보이는데 브라우저에서 보이지 않으면 입력이 확정되지 않은 것입니다. 실행한 세션을 닫기 전에 알려 주세요.

6. **(선택) 중복 방지 확인**: 3번을 한 번 더 실행하고 4번 결과가 그대로인지 확인합니다.

## 4. 사원 관리 시연 순서

백엔드(`.\gradlew.bat bootRun`)와 프론트엔드(`npm run dev`)를 실행하고 http://localhost:5173 을 엽니다.

1. **목록**: 12명, 요약 카드 전체 12 / 재직 10 / 퇴사 2, 재직·퇴사 배지, 퇴사일 표시, 비어 있는 항목 "-"
2. **상세**: 이름을 눌러 프로필·소속·연락처·재직 정보 확인
3. **사번 중복 확인**: 등록 화면에서 `e2019001` 입력 → 대문자 변환 후 "이미 사용된 사번입니다." / `E2026001` → "사용 가능한 사번입니다."
4. **입력 검증**: 하이픈 없는 전화번호, 잘못된 이메일 → 항목별 오류 문구
5. **등록**: `E2026001`로 가상 사원 등록 → 목록에 추가, 새로고침해도 유지
6. **퇴사 처리와 정정**: 수정 화면에서 퇴사 선택 → 퇴사일 필수, 입사일보다 이른 날짜 거부 → 저장 / 다시 재직으로 정정하면 퇴사일이 비워짐
7. **논리 삭제**: 5번에서 등록한 사원 삭제 → 목록에서 제외 → 같은 사번으로 중복 확인하면 "이미 사용된 사번입니다."
8. **장애 안내**: 백엔드를 끄고 목록을 새로고침 → "서버에 연결할 수 없습니다" 안내와 다시 시도 버튼

> 5~7번에서 등록·삭제한 사원은 개발 DB에 남습니다. 시연을 반복할 때는 `E2026002`, `E2026003`처럼 매번 다른 사번을 사용하세요.

## 5. 급여 관리 시연 순서 (포트폴리오용 시뮬레이션)

준비: 백엔드·프론트엔드 실행, 데모 사원 12명 반영(3장). 왼쪽 메뉴 **급여 관리**에서 시작합니다.

1. **급여 기간 목록**: 시뮬레이션 안내, 상태 배지(작성 중 / 확정), 기간별 인원·지급·공제·실지급 합계
2. **급여 기간 만들기**: 기본값(이번 달, 그 달 25일) → 만들기 → 상세 화면으로 이동
   - 같은 연월을 다시 만들면 "같은 연월의 급여 기간이 이미 있습니다."
   - 이미 시연용 기간이 있으면 새로 만들지 말고 그 기간을 사용합니다(8장).
3. **대상 사원 규칙**: 기간 상세 → **+ 급여 입력** → 사원 선택 목록에는 **그 달에 재직한 사원만** 표시
   - 2026년 기간: 재직 10명 (퇴사자 2명 제외)
   - (선택) 2025년 12월 기간: **11명** — 2025-12-31 퇴사자(E2023005 윤채원)도 12월에는 재직했으므로 포함
   - 이미 급여를 입력한 사원은 목록에서 빠집니다. 사원 관리 시연에서 사원을 추가 등록했다면 인원이 달라질 수 있습니다.
4. **급여 입력**: 아래 예시 입력값으로 입력
   - 금액 칸은 숫자만 입력되고 천 단위 쉼표가 붙음, 합계 미리보기가 바로 계산됨
   - 공제를 지급보다 크게 입력하면 빨간 경고 → 값을 되돌린 뒤 저장
   - 저장하면 급여명세서로 이동
5. **급여명세서**: 가상 회사명, 입력 당시 사원 정보, 지급 내역의 과세·비과세 표시, 공제 내역, 실지급액, 하단 시뮬레이션 안내
6. **인쇄 미리보기**: **인쇄** → 사이드바·버튼 없이 명세서만 A4에 표시, 시뮬레이션 안내 포함 (미리보기만 확인하고 닫아도 됨)
7. **수정**: 명세서 → **수정** → 사원은 바꿀 수 없음(읽기 전용), 금액 변경 후 저장 → 명세서에 반영
8. **2~3명 추가 입력**: 기간 상세의 인원·합계가 늘어나는 것 확인, 행을 누르면 각 명세서로 이동
9. **확정**: 기간 상세 → **확정** → 확인창 → 상태 "확정", 급여 입력·수정·삭제·지급일 수정 버튼이 사라짐
10. **확정 취소**: **확정 취소** → 확인창 → "작성 중"으로 돌아와 다시 수정 가능
11. **(선택) 삭제와 재입력**: 작성 중인 급여를 명세서에서 **삭제** → 확인창 → 같은 사원을 다시 입력할 수 있음

**예시 입력값** (시연을 빠르게 하기 위한 임의 숫자입니다. 실제 세액·보험료가 아니며, 요율로 계산한 값도 아닙니다.)

| 구분 | 항목 | 금액 |
|---|---|---|
| 지급 | 기본급 (과세) | 3,000,000 |
| 지급 | 식대 (비과세) | 200,000 |
| 공제 | 소득세 | 100,000 |
| 공제 | 국민연금 | 130,000 |
| | **실지급액** | **2,970,000** |

## 6. 연간 급여 집계 시연 순서 (포트폴리오용 시뮬레이션)

준비: 5장 9번처럼 급여 기간을 1개 이상 **확정**해 둡니다. 연간 집계는 **확정된 기간만** 합산합니다. 왼쪽 메뉴 **연간 급여 집계**에서 시작합니다.

1. **연간 급여 집계**: 귀속 연도 선택(주소의 `?year=`도 함께 바뀜) → 시뮬레이션 안내와 "집계 기준 (전문가 검증 전)" 안내
   - 요약 카드: 인원·확정 기간 수, 지급 합계(과세 / 비과세), 공제 합계, 실지급 합계
   - 사원별 표: 사번 순, 개월 수와 지급·과세·비과세·공제·실지급 합계
   - 확정된 급여가 없는 연도를 고르면 "○○년에 확정된 급여가 없습니다." 안내
2. **사원별 연간 상세**: 사원 행을 누름 → 월별 표(귀속 월, 지급일, 금액), 맨 아래 연간 합계 행, 항목별 연간 합계 표
   - 요약 카드 금액이 연간 집계 화면의 그 사원 합계와 같은지 확인
   - 월별 표의 **보기** → 그 달의 급여명세서로 이동, **연간 집계로** → 목록으로 돌아감
3. **(선택) 작성 중 기간 제외**: 기간 상세에서 **확정 취소** → 연간 집계를 새로고침하면 "작성 중인 급여 기간 N개는 합계에서 제외" 안내와 함께 합계가 줄어듦 → 확인 후 다시 **확정**
   - 이 단계는 개발 DB의 기간 상태를 바꿉니다. 끝나면 반드시 다시 확정해 두세요.

> "다음 해 지급"(예: 12월분을 다음 해 1월에 지급) 표시와 "삭제됨" 배지는 시연 순서에 넣지 않습니다. 보여 주려면 삭제할 수 없는 급여 기간을 새로 만들거나 사원을 삭제해야 하기 때문입니다. 두 경우는 자동 테스트로 확인했으며, 규칙은 8장에 설명합니다.

## 7. 연말정산 모의 계산 시연 순서 (포트폴리오용 모의 계산)

> 연말정산은 연도별 규칙으로 계산한 **모의 계산**입니다. 2025년 귀속은 소득세법·국세청 안내 조사 기준, 2026년 귀속은 소득세법·부칙 기준(국세청 2026년 귀속 안내 미확인, 금액 계산은 2025년 귀속과 같음)이며, 그 밖의 연도는 2025년 귀속 규칙으로 대체합니다. 전문가 검증 전이며, 지방소득세는 포함하지 않고, 일부 계산 방식은 가정입니다. 공식 연말정산 결과가 아닙니다.

준비: 해당 연도에 **확정된 급여**가 있어야 합니다(6장 준비와 같음). 왼쪽 메뉴 **연말정산**에서 시작합니다.

1. **목록**: 귀속 연도 선택 → 모의 계산 안내, 요약 카드(대상 인원·입력 완료, 추가 납부 합계, 환급 합계, 적용 규칙), 사원 표(입력함/미입력 배지, 총급여, 결정세액, 기납부세액, 추가 납부/환급)
   - 확정된 급여가 없는 연도를 고르면 "○○년에 확정된 급여가 없습니다." 안내와 **급여 관리로 이동** 버튼이 나오고, 요약 카드는 0명·0원으로 표시됩니다.
2. **계산 결과**: 사원 행을 누름 → 경고 목록, 7단계 계산표(신청액 중 한도를 넘어 적용되지 않은 금액은 "한도 초과 미적용"으로 표시), 계산에 쓴 급여 합계, "가정한 계산 방식"
   - 귀속 연도가 2025·2026년이 아니면 "2025년 귀속 규칙을 적용한 결과" 경고가 함께 나옵니다. 2026년이면 "국세청 2026년 귀속 안내는 확인하지 못했고 전문가 검증 전" 안내가 나오고, 자녀세액공제 자녀를 1명 이상 입력했다면 2017년생 주의 문구도 나옵니다.
   - 목록의 "적용 계산 규칙" 카드에 실제로 적용한 규칙 연도가 표시됩니다(예: 2027년을 고르면 "2025년 귀속", "2027년 규칙 미등록 → 2025년 귀속 규칙으로 대체").
3. **입력 자료 입력**: 결과 화면 오른쪽 위 버튼 → 인원 수와 예/아니요만 입력합니다(이름·주민등록번호는 입력하지 않음).
   - 인원 드롭다운: 아래로 열리면 위에서부터 0명 → 20명, 선택창이 화면 아래쪽이라 위로 열리면 선택창 바로 위가 0명이고 멀어질수록 숫자가 커집니다. 선택할 수 있는 최대값은 다른 입력에 따라 바뀝니다(예: 자녀 수는 부양가족 인원까지).
   - 화면 검증 예: 배우자 기본공제와 한부모 공제를 모두 "예"로 두고 저장하면 오류 안내가 나오고 저장되지 않습니다.
4. **(선택) 저장**: 저장 → 결과 화면으로 이동하며 "연말정산 입력 자료를 저장했습니다." 안내 → 목록 배지가 "입력함"으로 바뀌고, 결과 화면의 공제 금액과 경고가 입력값에 맞게 바뀝니다.
   - ⚠️ 저장하면 개발 DB에 기록되며 **삭제 기능이 없습니다**(8장).

> 급여가 적어 산출세액이 0원이면, 입력값을 바꿔도 결정세액은 0원이고 추가 납부/환급액(기납부세액 전액 환급)은 바뀌지 않습니다. 이때는 계산표의 공제 금액·"한도 초과 미적용" 표시와 경고 내용이 바뀌는 것으로 입력 반영을 확인합니다.

## 8. 급여 시연 주의사항

- 입력한 급여 기간과 급여는 **개발 DB에 저장**됩니다. 가상 데이터만 입력하세요.
- **급여 기간은 삭제할 수 없습니다**(삭제 기능 없음). 시연할 때마다 새로 만들지 말고 **시연용 기간 하나**를 계속 사용하는 것을 권장합니다.
- 급여는 **작성 중인 기간에서만** 수정·삭제할 수 있습니다. 확정된 기간은 **확정 취소** 후 수정합니다. 확정·취소 이력은 기록하지 않습니다.
- 급여를 입력한 뒤 사원 정보가 바뀌거나 사원이 논리 삭제되어도, 명세서는 **입력 당시 사원 정보**를 유지합니다.
- 금액은 시뮬레이션 값입니다. 소득세·지방소득세·4대보험료는 **자동 계산하지 않으며** 직접 입력한 값만 표시합니다. "비과세"는 분류 표시일 뿐 한도는 검사하지 않습니다.

**연간 급여 집계** (기준 근거: [tax-rules/income-attribution.md](tax-rules/income-attribution.md))

- **귀속 연도 기준**입니다. 귀속 월을 근로를 제공한 달로 간주하므로, 12월분을 다음 해에 지급해도 그 해에 합산하고 월별 표에 "다음 해 지급"으로 표시합니다.
- **확정된 기간만** 합산합니다. 작성 중인 기간은 제외하고 그 수를 안내합니다.
- 논리 삭제된 사원도 급여 기록이 있으면 포함하고 **"삭제됨"** 배지를 붙입니다. 사원 정보는 그 해 마지막 확정 급여 당시 기준입니다.
- 과세·비과세는 입력 당시 항목 구분으로 나누며, 비과세 한도(예: 식대 월 20만원)는 검사하지 않습니다.
- 전문가 검증 전이며 공식 원천징수·연말정산 자료가 아닙니다.

**연말정산 (모의 계산)** (규칙 근거: [tax-rules/year-end-settlement-2025.md](tax-rules/year-end-settlement-2025.md), [tax-rules/year-end-settlement-2026.md](tax-rules/year-end-settlement-2026.md), 요구사항: [requirements-year-end.md](requirements-year-end.md))

- 등록된 규칙은 2025·2026년 귀속입니다. 2026년 귀속은 소득세법·부칙으로 확인한 범위만 반영했고 금액 계산은 2025년 귀속과 같습니다(국세청 2026년 귀속 안내 미확인, 전문가 검증 전). 그 밖의 연도 급여에는 2025년 귀속 규칙을 적용하고 경고를 표시하며, 그 연도의 개정 사항은 반영하지 않습니다.
- 지방소득세는 포함하지 않습니다. 이번 범위에서 제외한 공제(신용카드·의료비·교육비·기부금·월세 등), 세액감면, 중도 퇴사자 정산 방식은 반영하지 않습니다.
- 공식 자료로 확인하지 못해 **가정**한 계산 방식이 있습니다: 비율 계산의 원 미만 버림, 세액공제 합계가 산출세액보다 크면 결정세액 0원, 소득공제 한도를 넘을 때의 적용액 표시 순서. 결과 화면에도 표시됩니다.
- **자녀세액공제 나이 기준은 연도별 안내만 표시합니다.** 이 프로젝트는 나이를 판단하지 않고 사용자가 입력한 "공제 대상 자녀 수"로 계산합니다. 입력 화면에는 2025년 8세 이상, 2026년 9세 이상(소득세법 부칙 법률 제21548호 제2조②), 2027~2029년 10~12세 이상·2030년 이후 13세 이상(**참고**, 계산은 2025년 규칙으로 대체), 2024년 이하 "나이 기준을 확인하지 않았습니다"로 안내합니다.
- **2017년생 자녀(2026~2029년 귀속)**: 부칙 제2조③이 2017년생에게 단계 기준을 적용하지 않는다고 정한 것은 법령 사실이고, 그래서 13세 기준이 적용되어 공제 대상이 아닐 수 있다는 것은 조문 구조에 따른 **해석(미확정)** 입니다. 화면에도 둘을 나눠 표시하며, 전문가 확인이 필요합니다.
- 비과세 한도를 넘는 달(예: 식대 월 20만원 초과)은 경고만 표시하고, 계산은 급여 입력 당시 과세 구분 그대로 합니다.
- 확정된 급여만 사용합니다. 작성 중인 급여는 제외하고 그 건수를 안내합니다.
- 입력 저장은 개발 DB(`year_end_input`)에 기록되며 **삭제 기능이 없습니다.** 같은 사원·연도로 다시 저장하면 같은 행이 수정되고, 모든 값을 0명·아니요로 저장하면 "본인 기본공제만" 상태로 되돌릴 수 있습니다(행은 남음).
- 이름·주민등록번호 등 개인 식별 정보는 입력하지 않습니다. 논리 삭제된 사원은 조회만 가능하고 입력 저장은 거부됩니다.
- **검증 범위**: 계산 로직·API 자동 테스트, 헤드리스 브라우저 점검, 사용자 브라우저 확인(목록·결과·입력 선택지·입력 저장 1건)까지 진행했습니다. 실제 모바일 기기와 화면낭독기로는 확인하지 않았습니다.

## 9. 문제 해결

- **연간 급여 집계 화면에 "–"만 보이거나, 새로 추가된 기능이 "찾을 수 없습니다"로 나올 때**: 백엔드가 기능 추가 전 코드로 실행 중일 수 있습니다. README의 [백엔드 다시 켜기](../README.md#백엔드-다시-켜기)를 따라 다시 실행합니다.
- **연말정산 화면에 "요청한 주소를 찾을 수 없습니다."가 나올 때**: 백엔드가 연말정산 API(4차) 추가 전 코드로 실행 중일 수 있습니다. 위와 같이 백엔드를 다시 실행합니다. 개발 DB에 V3 마이그레이션이 이미 적용되어 있으면 다시 켜도 테이블은 추가로 바뀌지 않습니다.
- **"서버에 연결할 수 없습니다"**: 백엔드가 꺼져 있습니다. 백엔드를 실행한 뒤 다시 시도합니다.
