# 1차 MVP 요구사항: 직원 정보 관리

이 문서는 1차 MVP에서 확정된 규칙을 정리합니다. 규칙이 바뀌면 이 문서를 먼저 수정합니다.

## 1. 범위

**포함**
- 직원 등록, 목록, 상세 조회
- 직원 정보 수정, 퇴사 처리, 논리적 삭제
- 필수 입력값 및 입력 형식 검증
- 사번 중복 확인

**제외 (추후 단계)**
- 검색, 페이지 나누기, 프로필 사진 업로드
- 상태 변경 이력 관리
- 부서·직급 목록(마스터) 관리
- 로그인·권한
- 근태, 월별 급여, 연간 급여 집계, 연말정산

## 2. 직원 정보 항목

| 항목 | 필수 | 규칙 |
|---|---|---|
| 사번 | 필수 | 3장 참고 |
| 이름 | 필수 | |
| 입사일 | 필수 | |
| 부서 | 선택 | 자유 입력 |
| 직급 | 선택 | 자유 입력 |
| 전화번호 | 선택 | 형식 검증 |
| 이메일 | 선택 | 형식 검증 |
| 재직 상태 | 자동 | 등록 시 `재직` 기본값 |
| 퇴사일 | 조건부 | 4장 참고 |

**수집하지 않는 정보**: 주민등록번호, 주소, 계좌번호 등 민감정보

## 3. 사번 규칙

- 영문과 숫자만 허용합니다. 공백과 특수문자는 허용하지 않습니다.
- 길이는 1~20자입니다.
- 저장할 때 **대문자로 통일**합니다. `E001`과 `e001`은 같은 사번입니다.
- 중복 확인은 재직·퇴사·**논리적 삭제된 직원을 모두 포함**합니다. 삭제된 직원의 사번도 재사용할 수 없습니다.
- 중복 시 삭제 여부와 관계없이 "이미 사용된 사번입니다"로 안내합니다.
- 등록 후에는 **수정할 수 없습니다.**
- 검증은 화면, 서버, DB(UNIQUE 제약) 세 곳에서 합니다. 서버 검증이 최종 기준입니다.

## 4. 재직 상태와 퇴사일

| 상태 | 퇴사일 |
|---|---|
| 재직 (`ACTIVE`) | 비어 있어야 합니다. 값이 있으면 오류입니다. |
| 퇴사 (`RESIGNED`) | 필수이며, 입사일보다 빠를 수 없습니다. |

- 퇴사 → 재직으로 되돌리기(퇴사 처리 정정)를 허용합니다. 이때 퇴사일을 비워야 하며, 서버는 퇴사일을 자동으로 지우지 않고 값이 남아 있으면 오류로 응답합니다.
- 입사일을 수정할 때도 퇴사일보다 늦어지지 않는지 다시 검증합니다.
- 상태 변경 로직은 한 곳에 모아 두어, 추후 상태 변경 이력 기록을 쉽게 추가할 수 있도록 합니다.

## 5. 삭제

- 실제로 데이터를 지우지 않는 **논리적 삭제**입니다.
- 삭제된 직원은 기본 목록에 표시하지 않습니다.
- 삭제된 직원은 상세 조회, 수정, 재삭제가 모두 불가능합니다("찾을 수 없음").
- 퇴사와 삭제는 다릅니다. 퇴사자는 목록에 계속 표시됩니다.

## 6. 직원 목록 표시 항목

사번, 이름, 부서, 직급, 입사일, 재직 상태

## 7. 데이터 및 보안 원칙

- 가상의 직원 데이터만 사용합니다.
- DB 비밀번호는 Git에서 제외된 `application-local.yml`에만 사용자가 직접 입력합니다. 채팅이나 코드에 입력하지 않습니다.
